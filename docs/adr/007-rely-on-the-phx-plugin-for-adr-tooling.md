# 007: Rely on the phx Plugin for ADR Tooling

## Context

[ADR 003][] ported the generator from [`todofixthis/phx-claude-siat`][phx-claude-siat]
into `scripts/adr/generate_index.py` and `scripts/frontmatter.py`, with their test
suite. An `adr_index` autohooks pre-commit hook regenerated and staged the index
whenever a commit staged an ADR, and the CI `adr` job regenerated it and failed on a
diff. ADR 003 already named the risk: the port is a copy, so an upstream change reaches
this repository only if someone re-ports it by hand.

[`phx:writing-adrs`][] now ships its own stdlib tool, [`adr.py`][], beside the skill.
It indexes, validates, scaffolds, supersedes, discharges and renumbers ADRs, and answers
which decisions bind a path. The phx plugin's hooks call it in Claude Code sessions:
they inject the decisions binding a file the first time a session touches it,
regenerate the index after a file-tool edit to an ADR, and report faults. They report
only; none blocks. The tool also installs as a `phx-adr` command, so CI can run it.

The two cannot run side by side. Each writes `docs/adr/INDEX.md` in its own format, so
`adr.py check` reports the ported generator's index as stale. And the plugin's hooks stay
silent unless the index's first line names `phx:writing-adrs`, which the ported
generator's header didn't, so here they never ran.

The maintainer has made the phx plugin canonical for ADR tooling, and
[`.claude/settings.json`][] enables it for Claude Code sessions in this repository.
Every ADR here so far was committed with a Claude co-author.

## Options

Options 2, 3 and 4 all drop the ported generator for `adr.py`'s index format, and so
share the migration; it does not rank them.

### Option 1: Do nothing

**Pros:** The pre-commit hook regenerates the index and blocks a faulty commit that
stages an ADR, wherever autohooks is active.
**Cons:** The phx plugin's hooks stay off, and `adr.py` can't be used here without
fighting the ported generator over the index. The port has to be kept in step with the
skill by hand.

### Option 2: The plugin's tool in sessions and in CI (Accepted)

Delete the repository tooling. Sessions get the plugin's hooks; a CI job runs
`phx-adr check` from the plugin at a pinned release's commit.

**Cons:** No local check blocks a commit; a fault from outside Claude Code is caught
only once pushed. Outside Claude Code nothing allocates a number or regenerates the
index, so the author runs `phx-adr` by hand. The pin needs bumping with each plugin
release.
**Risks:** Sessions load whatever plugin release is installed, not the pinned one. A
release that changes the index format leaves CI reporting the index stale right after
a session regenerates it, until the pin catches up.

### Option 3: The plugin's hooks alone

**Pros:** Nothing to pin.
**Cons:** Nothing outside a Claude Code session with the plugin checks the corpus, and
the hooks only report, so a fault from any other commit lands on `main` unnoticed. A
commit that rewrites the index's header line turns the hooks off without a report.

### Option 4: Vendor `adr.py` into the repository

**Pros:** A pre-commit hook could block faulty commits again, plugin or not.
**Cons:** A copy that drifts from the plugin — the failure ADR 003 accepted and this
ADR exists to remove.

## Decision

Option 2. It keeps one implementation of the conventions, maintained with the skill that
states them, and keeps the CI check the `adr` job already gave this repository. Option 3
would drop that check, leaving ADRs unchecked for any commit made outside Claude Code.

## Consequences

- `docs/adr/INDEX.md` is generated by `adr.py` in the skill's format, which switches the
  plugin's hooks on here.
- `scripts/` (the ported generator, parser and their tests) and `.autohooks/adr_index.py`
  are removed, along with the `adr_index` pre-commit hook and `scripts` from pytest's
  `testpaths`. ADR 004's `scope` drops `scripts/`, which no longer exists.
- The CI `adr` job and `AGENTS.md`'s `phx-adr` commands pin a release's commit, with
  its version in a trailing comment. A regex manager in `renovate.json` bumps every pin
  in one pull request; fix whatever the new release reports in that same pull request.
- The plugin is Claude Code's, so an agent in another harness gets no session hooks, and
  meets the conventions only through `AGENTS.md`, the skill and CI.
